# 기출문제 연습프로그램

이 프로젝트는 PDF 기출문제와 정답 파일을 기반으로 문제를 분해해 연습할 수 있는 **오프라인 단일 사용자 데스크톱/모바일 학습 앱**을 만드는 것을 목표로 합니다.

- 목적
- C# MAUI 기반으로 Windows, Android, iOS, Mac에서 동작하도록 설계된 기출문제 연습 앱을 구현
- PDF와 정답 텍스트를 업로드해 문제를 분해 저장
- 카테고리별로 관리하고 랜덤 출제로 반복 학습
- 오답 문제 중심 복습 흐름을 제공

## 중요
- 답변과 수정은 위 문서들에 적힌 합의사항을 기준으로 한다.
- 문서에 이미 합의된 내용을 누락하거나 반대로 문제처럼 다시 제기하지 않는다.
- 설계 가정, 제약, 결정 사항이 바뀌면 관련 문서를 즉시 갱신한다.
- 모든 대화 답변을 할 때 이 문서를 정독한다.

## 답변 및 기록 원칙

- 충분한 근거가 없거나 정보가 불확실한 경우 임의로 지어내지 않고 "알 수 없습니다" 또는 "잘 모르겠습니다"라고 명시한다.
- 답변 전 가능한 정보를 단계별로 검증하고, 모호하거나 출처가 불분명한 부분은 "확실하지 않음"이라고 표시한다.
- 최종 답변은 확실한 정보만 사용해 간결하게 작성한다.
- 추측이 불가피한 경우 "추측입니다"라고 밝힌다.
- 사용자의 문의가 모호하거나 추가 정보가 필요하면 먼저 세부 정보를 요청한다.
- 확인되지 않은 사실을 단정하지 않고, 필요한 경우 근거를 함께 제시한다.
- 출처나 근거가 있는 경우 해당 정보를 명시하고, 가능하면 관련 링크나 참고 자료를 간단히 요약한다.
- 답변에 사용자의 질문을 평가하는 표현을 넣지 않는다.
- 문서와 답변은 기본적으로 한글로 작성한다.
- 사용자를 지칭할 때 "네가" 같은 반말 표현을 사용하지 않는다.


## 주요 기능(현재 적용 범위)
- 카테고리 관리
  - 카테고리 생성/조회
  - 같은 파일명 업로드 시 기존 항목 수를 기준으로 덮어쓰기 확인
- 업로드/분석(현재 OCR 분석 반영)
  - 문항 PDF를 앱의 로컬 소스 폴더에 등록
    - 같은 폴더의 고유 임시 파일에 완전히 기록하고 PDF 헤더를 검증한 뒤 원자 교체하므로, 복사 실패 시 기존 PDF를 보존
    - 덮어쓰기·등록 문항 삭제·카테고리 삭제 확인창을 표시할 수 없으면 작업을 중단(fail-closed)
  - 등록된 PDF 목록에서 문항 파일명 선택
  - 정답맵이 비어 있어도 문항 후보는 `미정답` 상태로 저장 가능
  - 추후 `문항 반영`을 다시 실행해 같은 파일에 정답만 추가/갱신 가능
    - 부분 정답맵은 명시한 번호만 갱신하며, 누락된 번호의 기존 정답과 유형은 보존
    - `2:`처럼 번호 뒤를 비운 항목은 해당 번호의 기존 정답만 명시적으로 해제
  - 잘못된 정답맵, OCR 후보가 없는 분석, 후보에 없는 정답 번호, 중복/리셋 번호 등 구조 오류는 저장 전에 차단
  - `1,2,3` 처럼 `문항 순번` 없이 정답만 나열된 형식도 지원
    - 순번은 입력 순서(1번,2번,3번...)로 자동 적용됨
    - 공란은 해당 문항의 정답 미등록(빈칸)으로 반영됨
- `문항 반영` 실행 시 플랫폼 공통 OCR 파이프라인으로 PDF 분석을 수행해 결과를 저장
  - Windows: 플랫폼 PDF 렌더러와 Windows OCR 엔진 사용
  - Android: `PdfRenderer`와 한국어 ML Kit 텍스트 인식기를 사용하며 별도 명령행 도구가 필요하지 않음
    - 렌더링·이미지 압축·OCR은 UI 스레드 밖에서 실행하고, 취소 시 실행 중인 ML Kit 작업이 끝난 뒤 관련 리소스를 해제
  - Mac Catalyst: `pdftoppm`으로 페이지를 렌더링하고 `tesseract`의 TSV 결과로 텍스트·행 좌표·신뢰도를 추출
  - iOS: 외부 명령행 도구 실행이 제한되므로 현재 OCR 분석 미지원(플랫폼 전용 OCR 어댑터 필요)
  - Mac Catalyst용 실행 파일은 PATH 또는 앱 디렉터리 아래 `Tools*` 하위 경로(`Tools`, `Tools/mac` 등)에서 탐색
  - 렌더링/OCR 캐시는 PDF 내용 해시별 디렉터리로 분리하고, 콘텐츠별 잠금과 임시 PNG 검증·원자 게시로 동시 분석의 부분 파일 노출을 방지
  - 분석 중에는 진행률과 처리 속도를 표시하며, 실제 문항 저장이 시작되기 전까지 사용자가 취소 가능
  - 새 분석을 시작할 때 이전 요약을 지우고, OCR·구조 검증·저장·화면 갱신 상태를 구분해 표시합니다. 저장 성공 후 상태가 `저장 중`으로 남지 않습니다.
  - 분석 중에는 카테고리, 예상 범위, 정답맵, 덮어쓰기 설정을 잠가 시작 시점의 분석 대상과 화면 표시가 달라지지 않게 합니다.
  - 이미 등록된 동일 소스에서 덮어쓰기를 끄면 기존 이미지 경계는 유지하고 기존 번호의 정답만 갱신합니다. 재분석에서 새로 나타난 번호는 암묵적으로 추가하지 않습니다.
  - 구조 검증으로 저장이 차단된 PDF도 분석 패널의 `최근 분석 진단 보기`에서 즉시 원인을 확인할 수 있습니다.
  - 실패한 재분석 진단은 `latest-attempt`, 실제 반영된 결과는 `committed`로 분리하고, 저장 문항 검토 화면은 `committed` 진단만 읽어 동일 파일명 재시도나 구버전 파일과 이력이 뒤섞이지 않게 합니다.
  - 정답맵 텍스트(`번호:정답`) 업로드/불러오기
  - 정답맵 파싱 규칙: `번호:정답1|정답2`(객관식 다정답)
  - 문항 분할은 헤더 후보(`1.`, `1)`, `1번`, `문항 1`, `①`, `가.`, `A.`)를 모두 수집한 뒤 번호 연속성·헤더 형식·열 내 좌측 정렬·질문 문맥을 합산해 문서 전체의 최적 경로를 선택합니다.
  - 선택지 번호와 실제 문항 번호가 경쟁하거나, 같은 번호의 강한 후보가 둘 이상이거나, 한 OCR 행에서 여러 헤더가 검출되어 공간 경계를 확정할 수 없으면 임의로 자르지 않고 구조 오류로 저장을 차단합니다.
  - 원형 문자·영문·닫는 괄호처럼 선택지에도 흔한 번호 형식만 이어진 경우에는 문장이 질문처럼 보여도 문항열로 확정하지 않습니다. 반대로 질문 근거가 분명한 단일 `1.` 문항은 보존합니다.
  - 후속 페이지의 앞부분을 이전 문항의 연속 지문으로 보존하고, 번호가 없는 질문 문장을 누락 문항으로 생성하지 않습니다.
  - 명시된 공통 지문 범위는 이전 문항 본문과 분리해 대상 문항들이 공유합니다. 번호 범위가 없는 공통 지문 문구는 첫 문항 앞에 있을 때만 자동 공유합니다.
  - 문항 이미지는 OCR 글자 상자의 합집합이 아니라 분할 단계에서 확정한 페이지·열 전체와 다음 문항의 공유 경계로 자릅니다. 따라서 OCR이 읽지 못한 그림·표·수식도 문항 영역 안에 보존됩니다.
  - 여러 페이지·여러 열에 걸친 문항은 페이지·열별 이미지 조각으로 저장해 연습 화면에서 순서대로 표시합니다.
  - OCR 좌표가 합성값이거나 서로 겹치고, 3단·문항 중간 전폭 영역처럼 현재 안전하게 표현할 수 없는 배치이거나, 이미지 영역이 비었거나 다른 문항·공통 지문과 겹치는 경우에는 기존 추정 크롭으로 되돌리지 않고 구조 오류로 저장을 차단합니다.
- 연습 모드
  - 카테고리별 랜덤 출제
  - 사용자 입력을 채점한 뒤 현재 문항의 정오답을 유지하고, `다음 문제`를 눌러 이동
  - 객관식: 숫자 입력만 허용, 정답 중 하나와 일치하면 정답
  - 주관식: 공백 제거 후 대문자화한 값으로 비교
  - 연습 옵션: `정답 없는 문항 포함` 토글 가능 (끄면 정답이 등록된 문제만 출제)
  - 최종 점수는 채점 가능한 문항만 분모에 포함하고, 정답 미등록 문항은 `미채점`으로 별도 표시
- 오답 노트
  - 오답 문제만 모아보기
  - 오답을 다시 맞추면 목록에서 제거
  - 사용자 수동 삭제 가능
- UI/UX 상태 관리
  - 실제 페이지 폭을 기준으로 1열/2열 레이아웃과 문제 이미지 기준 폭을 다시 계산하므로 데스크톱 창 축소, 태블릿 분할 화면, 회전에 대응
  - 연습 화면은 하나의 스크롤 영역만 사용해 이미지 위 세로 스와이프가 답 입력 영역으로 이어지며, 검토 화면은 `Grid`의 남은 영역에 배치해 하단 잘림을 방지
  - 창 크기 변경은 짧게 모아 한 번만 반영해 드래그·회전 중 이미지 조각을 반복 생성하는 깜빡임을 줄임
  - 다음 문항 이동 시 확대율과 스크롤 위치를 초기화하고 답 입력 포커스와 스크린리더 안내를 복구하며, 검토 목록의 현재 문항을 강조해 보이는 위치로 이동
  - 핀치의 연속 상대 배율을 누적하고, 제스처 중에는 화면 변환만 미리 보여 준 뒤 완료 시 한 번만 이미지 확대율을 확정
  - 저장 PNG는 서명뿐 아니라 chunk 길이·CRC·`IHDR`/`IDAT`/`IEND` 완결성을 확인하며, 일부 또는 전체 조각을 열 수 없으면 경고와 OCR 텍스트 대체 표시 제공
  - 확대/축소 한계에서 버튼을 비활성화하고 터치 영역·스크린리더 설명을 보강
  - 진행 중인 연습은 확인 후 중간 종료할 수 있으며, 이미 저장된 오답 기록은 유지
  - 카테고리 추가·삭제, 등록 문항 삭제, 정답 파일 선택은 하나의 구조 변경 잠금을 공유해 PDF 분석과 교차 실행되지 않음
- 로컬 저장 안정화
  - JSON 저장소가 손상되었거나 비어 있으면 고유한 `.corrupt-*.json` 백업을 남긴 뒤에만 빈 상태 파일로 복구하며, 백업 실패 시 원본을 덮어쓰지 않음
  - 저장 경로별 공유 잠금과 고유 임시 파일·디스크 flush·원자 교체로 여러 저장소 인스턴스의 갱신 손실을 방지
  - 같은 파일을 전체 덮어써도 동일 문항 번호의 ID와 오답 이력을 보존하고 실제로 사라진 문항의 이력만 제거
- 오프라인 권한 정책
  - 현재 구현에는 광고 SDK가 없으므로 Android 인터넷/네트워크 상태 권한을 요청하지 않음
  - 원본 PDF·OCR 결과·학습 이력이 기기 백업으로 외부 이동하지 않도록 Android 자동 백업을 비활성화

## 사용 방법
1. 저장소 경로에서 솔루션 열기  
   - `PreviousPractice.sln`
2. MAUI 워크로드가 설치된 환경에서 프로젝트 복원  
   - `dotnet restore PreviousPractice/PreviousPractice.csproj`
3. 실행(예시)  
   - Windows: `dotnet build PreviousPractice/PreviousPractice.csproj -t:Run -f net9.0-windows10.0.19041.0`
   - Android: `dotnet build PreviousPractice/PreviousPractice.csproj -t:Run -f net9.0-android`
   - macOS: `dotnet build PreviousPractice/PreviousPractice.csproj -t:Run -f net9.0-maccatalyst`
   - iOS: `dotnet build PreviousPractice/PreviousPractice.csproj -t:Run -f net9.0-ios`

## 현재 실행/검증 상태
- Windows 측 .NET 9 SDK와 MAUI 워크로드 기준으로 Windows 타깃 빌드가 가능합니다.
- WSL 셸에는 `dotnet` 명령이 없으므로 이 환경에서는 `cmd.exe /c dotnet ...` 형태로 Windows SDK를 호출해 검증합니다.
- `cmd.exe /c dotnet build PreviousPractice/PreviousPractice.csproj` 기준으로 Android, iOS 시뮬레이터, Mac Catalyst, Windows 타깃이 경고 0개/오류 0개로 빌드됩니다.
- 표준 Debug/Release 빌드는 컴파일러·기본 분석기 경고 0개를 기준으로 확인합니다. 선택적 `Recommended`/`AllEnabledByDefault` 전체 규칙 감사의 기존 설계·성능·지역화 권고는 별도 정적 분석 부채로 관리합니다.
- `PreviousPractice.Tests`의 파서·OCR 분할·이미지 경계·반응형 UI 계산·저장소 회귀 테스트 117개가 통과합니다.
- Android/iOS/Mac Catalyst 실행은 각 플랫폼 SDK, 에뮬레이터/실기기, 코드 서명 환경이 필요합니다.
- Mac Catalyst OCR 경로는 외부 프로세스 실행 지원을 전제로 하므로 최소 지원 버전을 15.0으로 둡니다.
